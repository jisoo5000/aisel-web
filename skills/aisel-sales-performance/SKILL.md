# 에이슬 상품성과분석

기준 저장소는 [jisoo5000/aisel-web](https://github.com/jisoo5000/aisel-web)이다. 해당 체크아웃의 `docs/sales-performance.json`에서 구현·배포·첫 실제 집계 상태를 각각 확인한다. 스킬 ZIP만 별도 위치에 설치했다면 현재 작업 폴더에 문서가 있다고 가정하지 말고 기준 저장소에서 `docs/sales-performance.json`과 `docs/sales-performance.md`를 읽는다. 파일이 존재하거나 테스트를 통과했다는 이유만으로 운영 중이라고 판단하지 않는다. 실제 게시 성공, 확인 상품 범위의 순위 표시, 미확정 상품 해소와 첫 예약 실행 확인은 서로 구분해 기록한다.

사용자가 바꾸지 않은 제품 기준을 유지한다.

- 카페24의 실제 판매만 사용한다. 메타 성과와 수기 목표·달성률은 제품 순위에 합산하지 않는다.
- 한국 시간 어제까지 최근 7일의 순판매수량을 기본으로 직전 7일과 비교하고 28일 추세를 함께 제공한다. 기간 내 주문에 연결된 완료 취소·반품은 수량 증거가 일치할 때만 차감한다. 교환은 원품·대체품 관계를 대조해 중복 계산을 막고 불명확하면 보류한다. 신청 중인 수량은 완료 전 결제수량에 포함해 안내한다. 빈 요청수량은 0이나 완료수량으로 채우지 말고 직접 상세 증거로 판정한다. 순매출이 입증되지 않으면 미확인으로 남기고 판매수량은 유지한다.
- 수량 미확정 상품은 보류한다. 서버가 확인된 상품끼리의 순위·게이지를 제공하면 목록 상단에 그 범위를 명시하고 표시할 수 있다. 화면에서 전체 순위를 추정하지 않는다.
- 기존 사진과 품명·품번을 재사용한다. 2026-10-07부터 목록은 접기 없이 판매량·기간 주문 반품률을 숫자와 빨강/파랑 한 줄로 보여준다. 확인된 판매수량은 출시일·재고 부족에 따른 전체 판단 대기로 가리지 않는다. 원인·품질 평가는 재고/출시 근거가 없으면 여전히 보류한다. 기록은 별도 창이며 내부 영문 사유 코드를 노출하지 않는다.
- 기존 매일 한국 시간 오전 6시 예약 집계를 일반 코드로 실행한다. AI 호출이나 Codex 주기 작업, 임의의 주간 검토 요일을 추가하지 않는다.
- 2026-10-06 “해줘”로 상품성과분석 이름·기간·기록 방식의 앱 반영을 승인했다. 신상품은 실제 고객 진열·판매 시작 후 7/14일, 기존·스테디셀러는 7일 변화와 28일 추세로 검토한다. 비공개 등록일을 출시일로 쓰거나 미확인 분류를 임의로 정하지 않는다.
- 날짜별 집계와 주간 판단·근거·조치·다음 검토일을 남기며 겹치는 7일 합계를 누적하지 않는다. 핵심 SKU 역할이나 PDP 원인은 근거 없이 자동 판정하지 않는다. 별도 시즌 자산 30일 기준은 유지한다.

인증·집계·배포 작업 전에는 [운영 절차](references/operations.md)를 읽는다. 판매성과의 별도 Firebase 앱과 제한된 요약 경로를 유지하며, 기존 작업지시서 인증 및 자동 쓰기 콜백을 판매 로그인에 연결하지 않는다.

완료 작업 재사용으로 새 수집기 코드가 예약에 반영되지 않는 경우에는 운영 절차의 기존 요약 보존 재검증 준비를 따른다. 준비와 자동 진행을 분리하고 완료한 실행 이력을 덮어쓰지 않는다.

시작 API 본문은 `{}`이고 집계 날짜는 서버가 계산한다. 러너 내부의 기간 검증용 `runDate`를 시작 요청에 추가하지 않는다. 저장소 실행 파일과 테스트는 루트 `scripts/`와 `tests/`에 있다.

새로운 외부 변경 권한을 이 스킬로 추정하지 않는다. 현재 사용자 요청과 이미 확인된 승인을 적용하고, 승인된 작업은 중복 확인 없이 진행한다. GitHub·Drive 게시가 포함되면 비밀값과 실주문이 없는 전달 파일을 만든 뒤 승인 범위 안에서 게시한다.

운영 시트 중심 전환은 `docs/sales-performance.json`의 `designReviews`에 검토 중으로 기록되어 있다. 확정 운영 기준과 구분하고, 단순 의견 요청을 시트·앱·예약 변경 승인으로 해석하지 않는다. 구현을 요청받으면 최신 검토 상태와 실제 운영 시트 설정을 먼저 확인한다.

## 디자이너 목록 · 2026-10-07 최신 기준

`docs/sales-performance.json`의 `designerScanChange20261007`과 MD의 v101 절을 따른다. 목록에는 판매량·기간 주문 반품률이 항상 보이며 접기/펼치기와 큰 입력 폼을 넣지 않는다. 파랑은 높은 판매량·낮은 반품률, 빨강은 낮은 판매량·높은 반품률이다. 순판매 중앙값과 완료 반품/(순판매+완료 반품)의 합산 기준을 검색·분류 필터와 독립적으로 유지한다. 이는 같은 기간 확인 상품의 비교 표시이며 사용자가 정한 절대 목표·상품 품질 확정이 아니다. 기간·관찰 시각·분자/분모·이후 반품 미성숙을 표시/기록한다. 완료 취소를 분모에 포함하거나 반품/순판매로 과장하지 않는다. 미확인·0분모를 0%로 만들지 않는다.

기록 입력·표시 당시 스냅샷·계정 변경 캐시 삭제를 보존하며, 비동기 목록과 사진이 커져도 스크롤 버튼 상태를 다시 계산한다. UI 변경 후 `test-sales-scan.cjs`, 기존 상품 분석 및 화면·저장·가격 검사를 수행하고 모바일 넘침/기록창/실제 배포를 확인한다. 인쇄 시트는 직전 원본과 직접 비교하며 과거 전체 페이지 지문 기준을 임의로 재승인하지 않는다. 새 집계가 진행 중이면 현재 게시 자료의 기간을 그대로 읽고 신규 집계 완료와 구분한다.

2026-10-07 스크롤바 후속 기준: 아래 상품이 안 보인다는 신고에는 실제 wheel/아래 이동과 마지막 행 위치를 먼저 확인한다. 이 레거시 문서는 BackCompat/BODY 스크롤 루트이며 html thin 스크롤바가 숨김/overlay가 될 수 있다. v103에서 BODY overflow-y:scroll/stable gutter와 HTML overflow:visible로 기본 브라우저 스크롤바를 복원한다. HTML만의 gutter 설정으로 복원을 완료했다고 판단하지 않는다. 기존 열린 탭에서도 확인한다. body overflow 잠금이나 문서 모드 변경으로 기존 인쇄/작지 레이아웃을 바꾸지 않는다. 새로고침 후 실제 스크롤 트랙·마지막 행·모바일 넘침·인쇄 시트 보존을 확인한다.


## 2026-10-07 판매 중 상품 전용 후속 기획

`designerSimplificationPlan20261007`은 기획만이며 앱·집계 수정 권한이 아니다. 다음 구현 요청 시 사용자 최신 범위(카페24 현재 판매 중 상품만, 상태·분류 필터 두 줄 제거)를 우선한다. 현재 판매상태와 과거 판매이력을 구분한다. 반품률은 사용자가 말한 실제 출고분 대비 같은 출고분 완료 반품을 제안 중이며 현행 결제 주문 수량을 출고로 간주하지 않는다. 표시안·높음/낮음 비교 기준·표본·관찰기간은 미확정으로 보존한다. 미성숙 0반품을 파랑 낮음으로 확정하지 않는다. 이번 기획에 앱 HTML·수집기·예약 변경을 포함하지 않는다.


2026-10-07 최신 후속 확정: 반품률 >20%는 빨강 경고, 정확히 20%는 초과 아님. 전체 판매 비중은 같은 기간 해당 상품 순판매수량/현재 판매 중 전체 상품 순판매수량이며 검색·정렬과 독립이다. 0분모는 —, 불완전 집계는 확인 중. 재고 소진율로 혼동하지 않는다. 사용자 20% 기준이 앞선 상대 높음/낮음 제안보다 우선한다. 앱 구현은 여전히 기획만이며 외부 알림·예약을 추가하지 않는다. 오른쪽 스크롤바 항상 표시를 유지한다.


### v104 최신 오류 대응 기준

스크롤바는 새 탭 screenshot만으로 완료 판단하지 않는다. 사용자 기존 탭에서 DOM 고정 스크롤바가 보이고 직접 끌어 마지막 행에 도달하는지 확인한다. v104 이후 브라우저 native 표시 설정에 의존하지 않으며 키보드·휠·인쇄 제외·스크립트 실패 시 native fallback을 보존한다.

전체 netQty가 미확인인 v2 상품은 같은 최근 7일의 일별 확인 수량을 최소치로 보여 정렬할 수 있다. 7일 범위·중복 날짜·coverage를 검증하고 부분치임을 명시한다. 미확인 claim을 0으로 채우거나 다른 기간 수량을 섞지 않는다. 현재 판매 중 모든 상품 수량이 확인되기 전에는 전체 순위 번호와 상대 판매 높음/낮음 확정을 보류한다. 렌 고정 순위 대신 확인된 수량으로 정렬한다. claim 미해결과 화면 복원 완료를 구분한다.


### v105 사용자 확정 화면 구성

2026-10-07 파란색 삭제·연두색 유지 검토를 거쳐 코드 적용 승인. 상태·분류 버튼 두 줄, 분홍색 안내, 상품 개수, 긴 계산 설명은 목록 위에 다시 넣지 않는다. 검색·기간·갱신·판매순 정렬·사진/품명/품번·기록·고정 스크롤바를 유지한다. 비동기 내부 상태 노드와 로그인·기록 결과는 보존한다. 상품별 미확인을 0이나 확정치로 바꾸지 않는다. UI 정리와 집계 증거 해결은 별개이며 현재 요청 범위에 없는 수집기/집계/카페24 매핑/알림 변경을 합치지 않는다.
