# 에이슬 작업지시서 판매성과 v95

기준일: 2026-10-03 · 시간대: Asia/Seoul

## 목적과 확정 구성

판매성과를 제품 개발에 참고할 수 있는 성적표로 제공한다. 카페24 실제 판매를 사용하며 메타 광고 점수는 순위에서 제외한다. 수기로 목표수량·판매수량·달성률을 입력하는 방식 대신 실제 집계 결과를 표시한다.

목록은 순위, 기존 작은 제품 사진, 품명·품번, 판매 게이지와 한글 평가로 구성한다. 기존 이미지를 재사용하며 원본사진 복사본을 새로 저장하지 않는다. 성과 우수는 네이비, 보통은 블루그레이, 성과 부진은 채도가 높은 와인색 `#A3264C`, 판단 대기는 회색으로 표시한다.

제품을 펼치면 순판매수량, 확인 가능한 순매출, 취소·반품 수량과 판단 사유가 나온다. 기존 개선 기록은 해당 제품의 메모 필드만 읽고, 수정은 작업지시서를 여는 경로로 연결한다. 판매중·판매준비·전체 필터와 품명·품번 검색을 유지한다.

## 집계 기준

- 한국 시간 전날까지 연속 14일 동안 결제된 주문을 집계한다.
- 해당 주문에 연결된 취소·반품 수량을 제외한다. 다른 기간 주문의 반품을 현재 판매에서 무조건 빼지 않는다.
- 같은 제품의 색상·사이즈 옵션을 합산한다. 정확한 상품 연결이 안 되면 연결 확인 상태로 남긴다.
- 순판매수량으로 정렬하고 확인 가능한 순매출을 동률 비교에 활용한다. 매출 근거가 부족해도 확인된 판매수량을 숨기지 않는다.
- 순위와 성과 판정은 구분한다. 신상품·출시일 미확인·재고 이력 부족은 부진으로 단정하지 않는다.
- 예약 실행은 매일 오전 6시 한국 시간으로 준비한다. 일반 서버 코드가 수집·계산하므로 반복 실행에 AI 호출을 사용하지 않는다. API·호스팅·Firebase 사용량은 별도다.

## 상품 연결 근거

카페24 전체 725개 상품을 읽기 전용으로 확인해 공백만 정규화한 전체 상품명이 유일하게 일치한 9개를 찾았다. 추가로 사용자가 `AS-26F-KT-021` ‘밀로 라인 랩 니트’와 카페24 `product_no 1170` ‘밀로 라인 랩 니트 탑’이 같은 상품이라고 직접 확인했다. 확정된 연결은 총 10개이며 상세 근거는 [상품 연결 JSON](product-mapping.json)에 기록했다.

밀로의 별칭 승인은 이 한 쌍에만 적용한다. ‘탑’ 같은 단어를 모든 품명에서 지우거나 유사한 이름을 자동 연결하지 않는다. `AS-26F-CP-002`는 스트레이트 팬츠이고 참고 링크의 `product_no 951`은 부츠컷 제품이므로 연결에서 제외한다. 기존 품명·품번과 원본 작지는 변경하지 않았다.

확정 연결을 반영한 수집기는 `v17`에 배포됐고 소유자 읽기 점검도 성공했다. 전체 작지 52개와 카페24 상품 725개를 대조한 서버 결과는 연결 14개·충돌 2개·미연결 36개이며, 연결 14개에는 위 판매중 확정 상품 10개가 포함된다. 첫 실제 판매 스냅샷 게시와 소유자 화면의 판매중 상품 10개 표시를 확인했다. 다만 상품 연결·요약 게시 성공과 실제 순위 계산 가능 여부는 구분한다.

## 보관 데이터와 보안

요약 데이터에는 집계 기간·생성 시각·상품별 판매 숫자·순위·평가 상태만 허용한다. 주문 원문, 고객정보, 원본사진, 인증 토큰은 공개 프로젝트와 판매 요약에 포함하지 않는다. 기존 사진을 재사용하므로 이 기능 때문에 사진 사본이 매일 쌓이지 않는다.

기존 GitHub Pages와 승인된 Site 호스팅을 유지한다. Site 호스팅의 현재 공개 상태는 그대로 두고 판매 집계 API를 접근 인증과 별도 서비스 인증으로 보호한다. Firebase 규칙이 실제 권한을 검증하며 로그인 버튼은 보안 규칙의 대체 수단이 아니다. 판매 로그인으로 기존 작지의 시트 반영·사진 갱신 콜백이 실행되지 않도록 별도 앱을 사용한다.

권한 거절·자료 누락·상품 미연결은 판매 0과 구분한다. 마지막 정상 결과가 있는 단순 갱신 실패는 그 결과와 갱신 시각을 유지한다. 로그아웃·권한 상실 때는 판매 데이터 캐시를 제거한다. 불완전 집계를 정상 결과 위에 게시하지 않는다.

## 검증과 남은 작업

프런트엔드는 60개 검증과 인쇄 6개 검증을 통과했다. 320~1280px 화면, 정렬·검색·상세 펼침, 0과 미확인 구분, 한글 사유, 인증 분리, 로그아웃 중 응답 경합을 포함한다. 러너 150개 검증에 이어 첫 실제 요약 게시·재조회와 소유자 화면도 확인했다. 수동 실행 성공을 매일 예약 실행 성공이나 순위 완성의 증거로 확대하지 않는다. 최종 러너 설정은 전체 처리 최대 35분, 상태 조회 최대 300회, GitHub 작업 최대 40분이며 서버의 대기 권고는 0~300초만 허용한다.

시작 API 계약은 `POST /api/workorder-sales/jobs`에 JSON `{}`를 보내는 것이다. 서버가 한국 날짜를 계산한다. 러너의 내부 `runDate`는 반환된 집계 기간 검증에만 사용하고 시작 요청에 포함하지 않는다. 루트 `tests/`의 테스트를 사용하며 `runner/tests/`를 전제로 하지 않는다.

남은 작업은 수집기의 취소·교환 수량 증거 보강, 재집계·재조회, 서버가 제공하는 순위·게이지의 사용 가능 여부와 소유자 화면 확인이다. 미확정 수량을 0으로 바꾸거나 확인된 일부 상품만으로 전체 순위를 추정하지 않는다. 첫 오전 6시 예약 실행도 별도로 확인해야 한다. 수집기는 `v16` / `5ea57a840d1e2f7056cd0d57527b6cffadbc79a0`을 거쳐 승인 별칭이 포함된 `v17`에 배포했다. 시작 요청 오류 수정, API 접근 권한 등록, GitHub 비밀값 6개 설치, 최신 러너 `5dd7b1686dd60b36c9792f0e70cd2ab3193fddb2` 배포도 완료했다. 예약·수집기 배포, 실제 요약 게시, 사용할 수 있는 순위 완성을 각각 구분하며 추가 검증 후 [상태 JSON](sales-performance.json)을 함께 갱신한다.
